# Independent review: camera RAW to JPEG

**Reviewed:** 2026-11-22
**Branch/commit:** `feat/image-from-raw` at `e187b35444588157387746cbf7004e776b8e0b6d`; includes the uncommitted change to `plan.md`.
**Verdict:** Request changes.

## Scope and verdict

The request promises batch conversion of several image formats to JPG. This change implements the remaining RAW part of that promise: an active bilingual RAW card, JPEG-only UI, supported camera extension list, local LibRaw worker, and single-file or ZIP downloads. The other listed formats belong to earlier feature stages and are not reimplemented here. The new RAW path follows the approved plan’s separation from the earlier HEIC implementation.

The main conversion path is present, and the running app shows the intended RAW form. I found one acceptance gap: the RAW-specific 100 MiB bound is enforced after multipart parsing, so it is not a streaming bound when an operator configures the general per-file limit above 100 MiB.

## Finding

### P2 — The RAW-specific 100 MiB cap is checked after multipart parsing

`parse_limited_upload_form()` configures `LimitedMultiPartParser` with `settings.max_file_size_bytes` in `main.py:156`. `submit_job()` fully parses the multipart body before it calls `process_upload_form()` (`main.py:486-492`). The RAW-specific check is later, while copying the already parsed upload into the job directory (`main.py:1553-1560`). `MAX_FILE_SIZE_MB` is an operator-configurable setting with a default of 100 MiB (`config.py:14-34`, exposed in `compose.yaml`).

If an installation raises `MAX_FILE_SIZE_MB` above 100, a RAW upload between 100 MiB and that configured limit is accepted and spooled by the multipart parser before the route returns 413. This does not meet criterion 4’s requirement to reject the excess while streaming and before retaining it. The added `test_raw_api_rejects_files_over_native_decoder_limit` (`tests/test_raw_ops.py:191-201`) monkeypatches the RAW cap to two bytes and verifies the later route response; it does not prove that the parser rejects the RAW cap during parsing.
